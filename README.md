# 지하물류체계 구축을 위한 물동량 집중 구간 탐구

2022년 2학기에 수행한 탐색적 시각화 연구를 웹에서 살펴볼 수 있도록 재구성한 아카이브입니다. 당시 선택한 도로 구간과 지방우정청 권역별 배달물량을 살펴보며, 지하물류체계 도입을 후속 검토할 위치를 탐색합니다.

**[사이트 열기](https://hansol000808.github.io/logistics-flow/)** · 연구자 HAN JAEHYEOK

## 지도에서 살펴볼 수 있는 것

- 중소형 화물차와 대형 화물차 관점을 전환하고, 2022년 연구에서 선택한 구간을 비교합니다.
- 지도 또는 목록에서 구간을 선택해 2021년 조사 교통량과 양방향 합계를 확인합니다.
- 구간 이름을 검색하고 전국·수도권 화면을 전환합니다.
- 권역별 우체국 배달량을 면적에 비례하는 원과 수치로 확인합니다.
- 자료의 시점·단위·출처와 분석의 한계를 함께 읽습니다.

도로 구간은 당시 수동으로 선택한 고정 집합입니다. 공개본이 전국 전체 도로에서 최적 구간을 자동으로 찾아낸 것은 아닙니다. 당시 빨간 선 29개와 주황 선 12개 중 한 구간이 겹쳐, 고유 도로 구간은 40개입니다. 각 관점의 목록은 해당 집합 안에서 정렬합니다.

## 연구의 범위

도로 교통량은 차량 대수, 우체국 배달량은 물량으로 서로 다른 지표입니다. 서로 더하거나 동일한 수요의 척도로 취급할 수 없습니다. 지도상의 직선은 근사 좌표 사이의 연결이며 실제 도로 선형이나 제안 터널 노선이 아닙니다. 우체국 원은 해당 지방우정청 권역의 배달량이며, 권역 간 이동량을 나타내지 않습니다. 원래 연구의 비교 범위에 맞춰 제주를 제외한 8권역을 표시합니다.

이 연구는 실시간 서비스나 타당성 평가가 아닙니다. 건설비·지질·기존 지하 시설물·수요 전환·터미널 접근성·경제성은 추가 검토 대상입니다. 원래 보고서의 강한 입지 결론은 공개본에서 탐색적 후보 구간이라는 수준으로 정리했습니다.

서울 자치구 CJ 분석은 구별 기준월이 서로 다르고 자료 공개 범위의 추가 확인이 필요해 포함하지 않았습니다. 권역 간 OD 수송량도 원자료의 공개조건을 확정하지 못해 수치와 지도를 제외했습니다. 원본 보고서·발표자료·녹화영상도 그대로 게시하지 않습니다.

## 로컬 실행

사이트 실행에는 별도 빌드나 API 키가 필요하지 않습니다. 저장소 루트에서 정적 서버를 실행합니다.

```sh
python -m http.server 8000
```

브라우저에서 `http://localhost:8000/`을 엽니다. JSON을 읽기 때문에 `index.html`을 `file://`로 직접 열기보다 HTTP 서버를 사용해야 합니다. 지도 타일에는 인터넷 연결이 필요합니다. 화면에 필요한 타일만 불러오며, 서버에 이용자 입력이나 위치를 저장하지 않습니다.

## 데이터 재구성

공개 저장소에는 선별된 집계 JSON과 분석 방법을 담습니다. 원자료 CSV·XLSX와 원본 노트북은 포함하지 않습니다. 해당 자료에 합법적으로 접근할 수 있는 연구자는 다음과 같이 다시 생성할 수 있습니다.

```sh
python -m venv .venv
# 생성한 환경을 활성화한 뒤
python -m pip install -r requirements.txt
python scripts/build_data.py --help
```

```sh
python scripts/build_data.py --source-dir /path/to/authorized-source-files --notebook /path/to/original-notebook.ipynb --exclude-od --output /path/to/rebuilt-research.json
```

스크립트는 원본 노트북을 실행하지 않습니다. AST에서 리터럴 좌표와 구간 선택만 읽고, 입력 자료를 지역 이름과 구간 이름으로 결합합니다. 원자료를 자동 다운로드하거나 공개 승인 여부를 자동 판단하지 않습니다. 확인한 두 입력 파일의 SHA256이 같고 OD를 제외한 경우에만 검토 상태를 유지합니다. 다른 입력이나 OD 수치를 포함하면 `publicationReady: false` 상태로 생성됩니다. 출력 위치를 별도로 지정해 배포본의 덮어쓰기를 피할 수 있습니다.

검증 과정에서 교통량의 차종 합계·시간별 합계·양방향 구간 매칭을 확인했습니다. 우체국 자료는 당시 원본과 공식 과거 파일의 바이트가 일치합니다. 도로 자료는 공식 목록에서 같은 연도·파일명을 확인했지만, 공식 다운로드 서버 오류 때문에 파일 바이트의 동일성까지 확인하지는 못했습니다. 원본 자료가 바뀌면 같은 결과를 보장하지 않습니다.

## 파일 구성

```text
index.html              연구 소개와 지도 화면

app.js                  지도·검색·선택 상호작용
data/research.json      선별된 역사적 연구 집계
scripts/build_data.py   명시적으로 제공한 로컬 자료의 재구성
DATA_SOURCES.md         출처, 기준시점, 공개 범위
THIRD_PARTY_NOTICES.md  라이브러리·지도 저작권
vendor/leaflet/         Leaflet 1.9.4 및 원문 라이선스
site-manifest.json     공개 파일의 크기와 SHA256
```

## 배포

GitHub Pages의 `main` 브랜치 루트(`/`)를 사용합니다. `.nojekyll`을 포함한 빌드 없는 정적 사이트이며, 모든 내부 경로는 프로젝트 하위 URL에서 동작하는 상대경로입니다.

개발 원본과 공개 저장소를 분리했습니다. `.gitignore`는 검토한 파일만 허용합니다. 개인정보·학번·다른 학생 자료·수업자료·실습 API 키·원자료·대용량 영상·감사 결과는 이 저장소에 포함하지 않습니다.

## 출처와 이용조건

자료별 출처와 처리 기준은 [DATA_SOURCES.md](DATA_SOURCES.md), 지도 라이브러리와 배경지도는 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)를 확인하세요. 라이브러리의 라이선스가 연구 자료 전체의 이용허락을 대신하지 않습니다.
